# Skill: 转人工判断

## 触发场景

判断是否应将当前对话转交人工：用户要求、知识库无答案、高风险问题、情绪恶化、反复失败或无进展时。

## 触发条件

任一成立即转人工：

1. **用户明确要求转人工** — 直接同意，不再尝试自行解决
2. **低置信度** — 知识库无答案、答案相互矛盾、或无法定位到具体条目
3. **高风险问题** — 支付纠纷、账户安全、法律、合规类问题
4. **情绪恶化** — 用户明确不满、投诉，或出现情绪检测线索（见下节）
5. **重复失败** — 同一问题解答 3 次仍未解决
6. **对话无进展** — 约 10 轮对话仍未推进到解决或补充信息

项目特定阈值与范围以 [[domain/escalation-rules]] 为准。

## 情绪检测线索

用户重复同一问题、连续否定（「不是」「不对」）、使用感叹号或抱怨措辞（「太差了」「失望」「投诉」）→ 视为情绪恶化，优先转人工。

## 转人工流程

1. 明确告知用户将转人工及原因，语气诚恳
2. 生成交接信息（见下节模板）
3. 按 [[domain/escalation-rules]] 的人工通道告知下一步（入口、时间、联系方式）
4. 人工通道未配置：如实说明当前无人接听，建议留言或稍后再试；不得虚构通道或承诺响应时间

## 交接信息模板

转人工时输出以下信息（有则填，无则省略）：

1. 对话摘要（2-3 句）
2. 客户意图
3. 已尝试的解答
4. 情绪状态
5. 相关信息（订单号、账号等）

## 与「智能体委派」的区别

「转人工」是转给**人**（`support/escalation` 全流程），「委派」是转给**另一个智能体**（`delegate_agent`）——两者不可互换：

- 缺的是**可查的事实**（订单状态、库里的统计、日志），而自有接口查不到：先 `delegate_agent` 请对口智能体查回来，别因为「查不到」就转人工。
- 命中上面任一触发条件（尤其政策/合规/情绪类、用户明确要求人工）：**必须转人工**，不得用委派智能体敷衍——客户要的是「人」，给了另一个机器人等于没处理。
- 委派的子智能体产出**不是客服答复**：它只有事实，口径、语气、承诺边界仍由你按 `support/customer-reply` 统一输出。

## 不可转人工的情况

人工通道未配置且用户不接受等待：提供留言方式（如有）并说明下次联系建议携带的信息；仍无法解决时诚实告知，不假装转交，也不要用委派智能体冒充人工。
